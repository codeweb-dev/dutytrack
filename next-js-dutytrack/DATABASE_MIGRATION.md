# Database and data migration strategy

Plan only. No data moves in this task.

1. **Baseline**: obtain read-only production schema, migration history, row counts, orphan checks, enum frequencies, timestamp timezone, actual Spatie role/permission rows, file inventory and SQL driver. Compare to [DATABASE_SCHEMA.md](DATABASE_SCHEMA.md); source code alone cannot prove live data.
2. **Schema**: create reviewed Supabase SQL migrations in dependency order: identity/role map → profiles → assignments/requirements → attendance/duty/submissions/evaluations/tasks → chat/announcements/audit. Preserve unique/FK/index/cascade semantics. Treat Laravel `sessions`, `password_reset_tokens`, `cache*`, `jobs*` as runtime state, not automatic business imports.
3. **IDs**: retain legacy `public.users.id` bigint as application key and map it to unique `auth_user_id` UUID. Domain FKs keep bigint values; import parent rows first. This is the recommended design pending Phase 00 live-schema verification. Maintain a deterministic mapping manifest and verify referential integrity. `student_profiles.student_id` is a separate human-readable student number.
4. **Users/auth**: migrate user metadata, role membership and verified-email state. Supabase Auth password-hash import compatibility is OPEN QUESTION; rehearse with supported tooling or use reset/invite flow. Do not transfer Fortify 2FA secrets without a supported secure method; plan re-enrolment and user communication. Resolve roleless self-registration and inactive status behavior.
5. **Data**: snapshot and checksum source; import users/profiles/roles, assignments, requirements, attendance, duty, evaluations, tasks, notes, conversations/messages, announcements/audit, then submissions. Include coordinator conversations with null assignment. Preserve decimals and timestamp precision/timezone; compare dates around local midnight (APP_TIMEZONE in `.env.example` is UTC but runtime may differ).
6. **Files**: inventory `storage/app/public` and `public/profile`, static `public/requirements`; map profile and accomplishment paths to private Supabase buckets or public static assets as appropriate. Verify type, MIME, byte count, hash and relationship. Avoid importing unused fixtures or exposing personal directories.
7. **Validation**: compare counts by table/status/role, FK orphans, uniqueness, attendance-to-duty totals, evaluation rubric totals, report rendering, sampled records per role, attachment hashes and access-denied cases. Reconcile discrepancies before cutover.
8. **Rehearsal**: repeat import from a disposable snapshot; record duration, failures, duplicate handling and restartability. Freeze write window and delta strategy must be defined from real traffic patterns.
9. **Cutover**: back up source and target, place Laravel in read-only/maintenance mode, final delta import, rerun checks, switch routing, smoke-test all five roles and downloads/chat. Keep rollback target and DNS/session strategy documented.
10. **Rollback**: predefine trigger thresholds and owner. Restore routing to Laravel and only resume writes after deciding how to reconcile any Next.js writes; otherwise data diverges. Retain backups and change logs for agreed retention.

**Decision record template**: CURRENT | TARGET | WHY | MIGRATION IMPACT | validation evidence | approver. Required for every schema or behavior deviation.
